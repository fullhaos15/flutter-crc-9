# Отчёт по практической работе SRS 9

**Проект:** Post Explorer (практическая работа SRS 8). **Цель:** своя иконка, unit- и widget-тесты.

## 1. Launcher Icon
1. Иконка нарисована под тематику приложения (посты + поиск): `assets/icon/app_icon.png`, 1024×1024, PNG, без прозрачности (для iOS).
2. Для Adaptive Icon: `assets/icon/app_icon_foreground.png` (прозрачный фон) + цвет фона `#3F51B5` (тот же индиго, что `colorSchemeSeed` приложения).
3. Пакет: `flutter pub add dev:flutter_launcher_icons`.
4. Настройка в конце `pubspec.yaml`:
```yaml
flutter_launcher_icons:
  android: true
  ios: true
  image_path: "assets/icon/app_icon.png"
  min_sdk_android: 21
  remove_alpha_ios: true
  adaptive_icon_background: "#3F51B5"
  adaptive_icon_foreground: "assets/icon/app_icon_foreground.png"
```
5. Генерация: `dart run flutter_launcher_icons` (папки `android/` и `ios/` должны существовать — `flutter create . --platforms=android,ios`).
6. 📸 *Скриншот: иконка на главном экране эмулятора.*

## 5. Контрольные вопросы
1. **Launcher Icon** — иконка приложения на главном экране и в списке приложений.
2. **flutter_launcher_icons** — автоматически создаёт иконки всех нужных размеров для Android и iOS из одного PNG.
3. **Где настраивается** — в `pubspec.yaml`, секция `flutter_launcher_icons`.
4. **Unit Test** — проверка отдельной функции/метода/класса без интерфейса.
5. **Отличие** — Unit проверяет логику и результаты вычислений; Widget — отображение и взаимодействие (текст, кнопки, поля) в тестовой среде.
6. **expect()** — сравнивает фактический результат с ожидаемым (matcher); при несовпадении тест падает.
7. **test()** — объявляет один unit-тест: описание + асинхронная функция с проверками.
8. **testWidgets()** — объявляет widget-тест; даёт `WidgetTester` для построения виджетов, нажатий (`tap`), ввода (`enterText`) и перерисовки (`pump`).
9. **flutter test** — находит файлы `*_test.dart` в `test/`, запускает все тесты и выводит результат.
10. **Зачем тестировать до публикации** — найти ошибки раньше, чем их найдут пользователи; безопасно менять код (тесты ловят регрессии); дешевле исправлять до релиза.

## 6. Что объяснить преподавателю
- Почему тестируем `Validators`: чистая функция, легко проверить границы.
- Почему `FakePostApi`: тест не зависит от интернета и сервера.
- `pump()` — один кадр, `pumpAndSettle()` — пока не закончатся анимации и асинхронные операции.
